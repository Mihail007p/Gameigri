## 4. Решения и почему так

| Решение | Причина |
|---|---|
| Один файл `index.html`, без сборки и зависимостей | Открывается двойным кликом, работает в превью и офлайн; легко отдать/переслать |
| Машины и трасса рисуются кодом (Canvas), а не спрайтами | Не нужны ассеты и загрузка файлов — каркас запускается сразу; спрайты — в бэклоге |
| Логика и настройки в одном объекте `CFG` | Баланс правится в одном месте, без поиска «магических чисел» по коду |
| Спавнер не заполняет все полосы сразу | Иначе игрок умирает без возможности уйти — это не сложность, а нечестность |
| Тесты без браузера (DOM-заглушки + ручная прокрутка кадров) | В окружении нет Chrome/Playwright; такой стенд быстрый (<1 с) и детерминированный |
| Тесты запускаются как обычный node-скрипт | Не нужны npm-пакеты и `npm install` — важно для продолжения в чистой среде |
| `window.Gameigri` с внутренними объектами | Удобно для автотестов и для отладки из консоли браузера |
| Отдельный `PROGRESS.md` в репозитории | Репозиторий доступен из любой сессии и машины; чат со временем теряет контекст |

## 5. Найденные и исправленные баги (полезно знать, чтобы не вернуть)

1. **Отрицательный шаг времени → дистанция уходила в минус.**
   В игровом цикле `dt` клэмпился только сверху (`Math.min(dt, 0.05)`), поэтому при рассинхроне
   часов (или в тестовом стенде) `dt` становился отрицательным, и счёт «уезжал» в −6·10¹⁰ метров.
   **Фикс:** `clamp((now - last)/1000, 0, 0.05)` — ограничение с двух сторон.
2. **Утечка памяти: машины, ушедшие за верх экрана, не удалялись.**
   Если скорость трафика выше скорости игрока, машина уходит вверх и висела в массиве навсегда.
   **Фикс:** `offscreen` учитывает и выход за верхнюю границу (`y < -H/2`).
   **Как ловится тестом:** раздел «3. Трафик» — держим тормоз 15 сек и проверяем размер массива.

Отдельно (в стенде, не в игре) нашлись две ошибки самих тестов: не отпущенная клавиша руля
делала проверку границ пустой, а отсутствие отслеживания `Game.state` маскировало рестарты.
Обе исправлены: теперь тесты проверяют упор ровно в границу (`x = 87.0` и `393.0`) и считают аварии.

## 6. Как продолжить в другом чате (пошагово)

1. Откройте репозиторий: https://github.com/Mihail007p/Gameigri
2. Прочитайте `PROGRESS.md` (этот файл) и `AGENTS.md`.
3. Вставьте в новый чат:

```
Проект: Gameigri — https://github.com/Mihail007p/Gameigri
Прочитай PROGRESS.md и AGENTS.md из этого репозитория
(https://raw.githubusercontent.com/Mihail007p/Gameigri/main/PROGRESS.md),
пойми текущее состояние и продолжи работу. Задача: <что нужно сделать>.
Перед коммитом запусти node tools/test_game.js (все проверки должны быть зелёными)
и зафиксируй изменения в PROGRESS.md.
```

4. Публикация изменений: `bash tools/gh_push.sh "feat: описание"` → ввести одноразовый код на
   https://github.com/login/device (15 секунд, пароль не нужен).

**Проверка среды в новой песочнице:** `node --version` (нужен для тестов), `curl -sS -o /dev/null -w '%{http_code}' https://api.github.com` → `200`.

## 8. Правило ведения журнала (обязательно)

При **каждом** изменении проекта:

1. Добавить строку в «Хронологию изменений»: дата/время, что сделано.
2. Обновить «Текущее состояние», если изменился состав файлов или статусы.
3. Закрыть пункты бэклога, добавить новые.
4. Прогнать `node tools/test_game.js` — все проверки должны быть зелёными.
5. Закоммитить журнал **вместе** с изменением и запушить (`bash tools/gh_push.sh`).
6. **Ничего не оставлять только в рабочей области.** Любой файл, который нужен завтра, должен быть
   в коммите: рабочая область одноразовая и в новой сессии её не будет.

Правило действует и для AI-агентов — оно продублировано в `AGENTS.md`.
