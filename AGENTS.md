# AGENTS.md — инструкции для AI-агента и для новой сессии

Этот файл читается первым при возобновлении работы над проектом **Gameigri**.

## 0. Быстрый контекст

- Репозиторий: `https://github.com/Mihail007p/Gameigri` (публичный, ветка по умолчанию `main`)
- Что это: аркадные гонки — один файл `index.html` (Canvas 2D, ванильный JS, без зависимостей и сборки)
- Владелец: `Mihail007p`
- Главный документ состояния: **`PROGRESS.md`** — читать целиком перед любыми действиями
- **Память проекта живёт в GitHub, не в рабочей области.** Рабочая область одноразовая: если файл
  нужен завтра — он должен быть закоммичен и запушен. Восстановление в пустой среде: `bash tools/restore.sh`

## 1. Обязательные правила работы

1. **Ведение журнала — обязательно.** Любое изменение → запись в `PROGRESS.md`:
   - «Хронология изменений» — новая строка с датой и сутью;
   - «Текущее состояние» — обновить при изменении структуры или статусов;
   - «Бэклог» — закрыть сделанное, добавить появившиеся задачи.
2. **Перед коммитом прогнать тесты:** `node tools/test_game.js` → должно быть `✅ ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ` (exit 0).
   Новую механику — покрывать новой проверкой в этом же файле.
3. **Коммит = код + журнал.** Не коммитить изменение без записи в журнале.
4. **Сообщения коммитов:** короткие, по-русски, с префиксом: `feat:`, `fix:`, `docs:`, `chore:`, `test:`, `tools:`.
5. **Никаких секретов в репозитории.** Токены — только в переменных окружения или в одноразовой сессии,
   никогда в файлах, `.git/config`, URL remote, истории коммитов. Перед коммитом проверять на
   `ghp_`, `gho_`, `github_pat_`, `x-access-token`.
6. **Не ломать `main`.** Крупное изменение — ветка + pull request.
7. **Правило «продолжаемости»:** после сессии в `PROGRESS.md` должно быть однозначно понятно:
   что сделано, что дальше, какие команды запускать.

## 2. Проверка и публикация

```bash
bash tools/restore.sh                    # поднять проект из GitHub в пустой среде (клонирование + тесты)
node tools/test_game.js                  # автотесты логики и баланса (без браузера)
python3 -m http.server 8000              # посмотреть игру локально
bash tools/gh_push.sh "feat: описание"   # commit + push; тесты прогоняются, при провале пуш отменяется
bash tools/gh_push.sh --pages            # то же + включить GitHub Pages
bash tools/deploy_new.sh Name "описание" # создать НОВЫЙ репозиторий из папки
```

Публичный сайт (после включения Pages): `https://mihail007p.github.io/Gameigri/`
Состояние репозитория без авторизации: `curl -sS https://api.github.com/repos/Mihail007p/Gameigri`

## 3. Архитектура игры (внутри index.html)

| Блок | Назначение |
|---|---|
| `CFG` | весь баланс: скорости, габариты, полосы, интервалы спавна, ключ рекорда |
| `Store` | обёртка над `localStorage` в try/catch (в песочнице/приватном режиме падать нельзя) |
| `Input` | клавиатура + тач-кнопки, сброс зажатых клавиш при потере фокуса |
| `Road` | геометрия дороги, полосы, прокрутка разметки |
| `Car` / `PlayerCar` / `TrafficCar` | отрисовка, AABB-столкновения, руление, крен |
| `Spawner` | спавн трафика; **всегда оставляет минимум одну свободную полосу** |
| `HUD` | дистанция, скорость, полоса скорости, рекорд |
| `Game` | состояния `menu/play/pause/over`, игровой цикл с `dt = clamp(..., 0, 0.05)` |

**Отладочный хук:** `window.Gameigri = { Game, CFG, Road, Spawner, Car, PlayerCar, TrafficCar, Input }` —
использовать в тестах и для отладки из консоли браузера.

## 4. Как проверять результат

- Тесты: `node tools/test_game.js` (стенд подменяет DOM и canvas, крутит кадры вручную — браузер не нужен)
- Глазами: открыть `index.html` (или `python3 -m http.server 8000`)
- Логика в консоли браузера: `Gameigri.Game.state`, `Gameigri.Game.cars.length`, `Gameigri.CFG`
