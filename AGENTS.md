Этот файл читается первым при возобновлении работы над проектом **Gameigri**.

## 0. Быстрый контекст

- Репозиторий: `https://github.com/Mihail007p/Gameigri` (публичный, ветка по умолчанию `main`)
- Тип проекта: статичный сайт/игра на чистом HTML, без сборки и зависимостей
- Владелец: `Mihail007p`
- Главный документ состояния: **`PROGRESS.md`** — читать целиком перед любыми действиями

## 1. Обязательные правила работы

1. **Ведение журнала — обязательна.** Любое изменение (код, файлы, решения) → запись в `PROGRESS.md`:
   - раздел «Хронология изменений» — новая строка с датой, сутью и хешем коммита;
   - раздел «Текущее состояние» — обновить, если изменилась структура или статусы;
   - раздел «Бэклог» — закрыть сделанное, добавить появившиеся задачи.
2. **Коммит = журнал.** Не коммитить изменение без соответствующей записи в журнале.
3. **Сообщения коммитов:** короткие, по-русски, с префиксом типа: `feat:`, `fix:`, `docs:`, `chore:`, `tools:`.
4. **Никаких секретов в репозитории.** Токены — только в переменных окружения или в одноразовой сессии, никогда в файлах, `.git/config`, URL remote и в истории коммитов. Перед коммитом: проверка на `ghp_`, `gho_`, `github_pat_`, `x-access-token`.
5. **Не ломать `main`.** Если изменение крупное — ветка + pull request.
6. **Правило «продолжаемости»:** после каждой сессии в `PROGRESS.md` должно быть однозначно понятно: что сделано, что дальше, какие команды запускать.

## 2. Публикация изменений на GitHub

```bash
bash tools/gh_push.sh "docs: обновление журнала"
```

Скрипт:
- скачает `gh` CLI, если его нет;
- попросит владельца ввести одноразовый код на https://github.com/login/device (Device Flow, пароль не нужен);
- закоммитит и запушит `main`;
- удалит токен после пуша.

Отзыв доступа: GitHub → Settings → Applications → GitHub CLI → Revoke.
